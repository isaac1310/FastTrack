## Build and deploy

`fast-tracker.html` (shell + CSS), `app.js` (data + pure logic), `ui.js` (render),
`selftest.js` are the only files edited. `deploy/` and the root `demo-*.html` are
generated by `node build.mjs` and git-ignored; Vercel runs the build on push, so
committing a stale copy is impossible.

The build **throws on a syntax error** in any source file rather than shipping a
broken app, and bumps the service worker cache key to match `APP_VERSION`.

## Hard constraints

Full list in `DESIGN-BRIEF.md` §3. The four that have already caused shipped bugs:

1. **`render()` restores focus and caret.** The day screen has six text
   inputs; slot text goes to a draft on `input`, never to the doc, and
   `captureFocus()`/`restoreFocus()` bracket every rebuild. `tick()` returns
   early on the day and week routes. Without this, typing is destroyed by any
   state change — the v1 date-picker bug, but constant.
2. **Tags are repeatable buttons, not checkboxes.** A binary control cannot
   represent two carbs, which would make the "second carb" flag unreachable.
   The day screen records what happened; it does not forbid.
3. **Every number needs `class="n"`** (`direction:ltr; unicode-bidi:isolate`).
   Without it RTL moves a leading minus to the trailing side and `-0.9` renders
   as `0.9-`.
4. **Never put two numbers around a separator.** `99.0/57.4` reorders to
   `57.4/99.0` and silently swaps the values. Label each number.
5. **`render()` / `tick()` split.** `tick()` patches text and geometry by id
   only. Touching `innerHTML` on a container holding an input closes an open
   date picker mid-use.
6. **Meat is tracked as a digestive burden and a streak, not as a nutrient.**
   Slower gastric emptying is measurable and may be stated. "Clean of meat"
   is a fact about what you ate — never detoxification, never toxin
   accumulation. The traditional "heavy/guru" framing belongs in the
   Ayurvedic section, not the physiology.
7. **The Ayurvedic lines live inline in the body-status card, at the user's
   explicit request — but each is labelled "במסורת האיורוודית" and carries the
   not-evidence-based note.** They describe state, never prescribe, and no
   constitution is asked or stored.
8. **Gluten copy leads with the blinded evidence.** Without celiac or a
   diagnosed sensitivity there is no established physiology to a gluten-free
   streak; in blinded challenges only ~8% of self-identified sensitive people
   reacted to gluten alone, and the felt improvements mostly trace to FODMAPs
   or fewer baked goods. The celiac test-before-elimination warning stays.
9. **Abstinence-timeline claims carry their population.** The measured alcohol
   improvements (liver enzymes 5–7d, BP ~2wk, insulin resistance ~25% at 4wk)
   were measured in REGULAR drinkers who stopped; the copy must say so. Meat's
   only day-scaled marker is TMAO (~4 weeks, short-term findings inconsistent);
   "lighter" is a report, not a measurement.
10. **Migrations speak the SOURCE version's vocabulary.** The v3 converter
   lists its keys explicitly. Iterating the current `INTAKE_ITEMS` silently
   dropped every count whose key had been renamed.
11. **When two causes are both visible, name both.** A headache at 8h since
   coffee during a 14h fast has two plausible sources — falling caffeine and
   sodium loss — and the app cannot tell which. `headacheAmbiguous()` exists
   so it says so instead of confidently blaming one.
12. **Withdrawal copy applies to regular users only,** and must say so. Someone
   who drinks coffee occasionally does not get caffeine withdrawal.
13. **Live body estimates are estimates, and must say so.** `caffeineNow()` and
   `alcoholNow()` are built from typical values (~100mg a cup, ~5h half-life,
   ~1 drink/hour) that vary hugely between people. Backdated entries carry
   `approx` and are excluded from them — claiming a dose from last Tuesday is
   circulating now would be inventing data.
14. **Never claim causation from the intake table.** Five weeks is far too
   small a sample, and weight moves with sleep, salt and everything unlogged.
   Show the columns side by side; refuse a read below 4 weeks; flag any week
   fitted from fewer than 4 weigh-ins.
15. **Pace math fits the RAW points, never the smoothed series.** An EMA lags,
   which biases its slope toward zero — fitting it reported −0.46 kg/week on a
   true −0.91, i.e. "behind pace" while exactly on pace. `smoothWeights()` is
   presentation only; `trendFit()` is the number.

Contrast: every text colour is annotated with its measured ratio in the
stylesheet. Compute before changing one — do not judge by eye.

## Verifying a change

```bash
node build.mjs
```

Then `__selftest()` in the console, or open with `?dev=1`. Run **four**
combinations: 412px and desktop, each in light and dark. A run in one theme is
never evidence about the other. Expect `177 passed, 0 failed, 1 skipped` at each; the skip is the
opposite width's layout check and must state its reason. **A skip without a
reason is a failure, and a run with skips is never "all passed."**

Then the human pass: `tests/TEST-PLAN-v3.0.0.md`.

Verify UI in a real browser before claiming it works. Every visual bug in this
project so far was invisible in code and obvious on screen.
